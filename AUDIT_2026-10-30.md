# HNL engineering audit — 2026-10-30

## Evidence reviewed
- Ffiber Research: research.py, nationwide.py, automated test sources, GitHub Actions configuration.
- HNL opportunity radar: catalog and sales modules, existing AGENTS.md/README, test files.

## Changes actually shipped
1. `catalog/app.py`: deterministic project-source deduplication, conservative automatic review, no overwrite of manually verified status/evidence, independent placeholders for unknown companies, project URL identifiers retained.
2. `sales/app.py`: reliable decimal input validation, cent accounting, immediate transactional locks for payments, overpayment rejection.
3. `cloud/import_nationwide.py`: explicit CLI PostgreSQL importer, uses DATABASE_URL from environment, parameterized SQL, one transaction, idempotent source links. Never auto-confirms crew demand.
4. PostgreSQL additive migrations `001_hnl_v2.sql`, `002_payment_guard.sql`, `003_invoice_amount_guard.sql`, `004_actionable_view.sql` applied successfully to Neon.
5. Added regression tests for contract amounts, partial payments, unknown companies, project URLs, import mapping and manual review retention.
6. Ffiber Research location attribution changed: query state is not automatically verified construction location.
7. Public website crawler honors robots.txt and revisits independent seeds even on the same domain.

## Verified on Neon
- Seven new relational tables and two views exist in schema `hnl`.
- Two financial triggers exist.
- Live transactional rollback-only test confirmed the DB rejects (a) paying $13 against a $10 invoice and (b) reducing a $10 invoice to $5 after $8 paid.
- No audit test records remained. Existing public schema untouched.
- Database currently has zero production leads/contracts/invoices. No evidence of an operational dashboard.

## IMPORTANT — Not production ready
- Python regression tests are present but have **not** been proven passing in a clean runner in this audit. Do not claim 100% runtime correctness.
- The Neon importer has not been executed with valid production DATABASE_URL / psycopg installed in a production runner.
- No authenticated two-user browser interface for Victor and Mauro is deployed or tested; row-level security is not enabled, so expose the data only through an authenticated backend with least-privilege credentials.
- A 50-state search workflow is configured, but actual fresh lead volume, query failure rate, and signal precision are not validated.
- `nationwide.py` classifies index snippets; it does not verify contractor identities, award documents, or real open crew calls.
- Shared CRM reconciliation, invoice-to-work-items association, authorized edits, audit trails, tax/retainage/change orders, unique payment references and invoice lifecycle require further product development.
- GitHub Actions email notification settings are not modified by this audit.

## Production acceptance checklist
- [ ] Clean install and all regression tests pass without relying on network or live secrets.
- [ ] Search sample verified against originals: false positives, duplicates, timestamps, state and contractor attribution.
- [ ] Production importer integration test on isolated database branch; idempotence and failure rollbacks verified.
- [ ] Authentication, audit history, role authorization, least-privilege credentials, backup/restore tested.
- [ ] Work orders/price lists, approved quantity, invoices, payments, adjustments and reconciliation tested end-to-end.
- [ ] Two authorized users see consistent changes on separate devices.
- [ ] Deploy monitored UI, safely enable scheduled runs after verified operation.

This audit intentionally preserves existing data and does not claim the platform is live.
